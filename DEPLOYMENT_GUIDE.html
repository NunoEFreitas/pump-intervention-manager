2. Phase 1 — Install Server Software

STEP 1 Install Node.js

  1. Open a browser on the server and go to nodejs.org
  2. Download the LTS installer (Windows 64-bit .msi)
  3. Run the installer with all default options. Make sure "Add to PATH" is checked.
  4. Open PowerShell as Administrator and verify:
node -v
npm -v

Both commands should print version numbers (e.g. v20.x.x and 10.x.x).

STEP 2 Install Git

  1. Go to git-scm.com/download/win and download the 64-bit installer.
  2. Run the installer. During setup:
    • Select "Git from the command line and also from 3rd-party software"
    • All other options can stay as defaults.
  3. Verify in PowerShell:
git --version

STEP 3 Install PM2 (process manager)

PM2 keeps the Next.js app running and restarts it automatically if it crashes or the server reboots.

npm install -g pm2
npm install -g pm2-windows-startup
pm2-startup install
Note: If PowerShell blocks npm global installs, run: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser

3. Phase 2 — PostgreSQL Database Setup

STEP 4 Install PostgreSQL 16

  1. Go to postgresql.org/download/windows and download the PostgreSQL 16 installer.
  2. Run the installer as Administrator. During setup:
    • Components to install: PostgreSQL Server, pgAdmin 4, Command Line Tools
    • Data directory: leave as default (C:\Program Files\PostgreSQL\16\data)
    • Set a strong password for the postgres superuser — write it down!
    • Port: 5432 (default)
    • Locale: leave as default
  3. Finish the installer. PostgreSQL will start automatically as a Windows Service.
  4. Verify the service is running:
Get-Service -Name "postgresql*"

You should see postgresql-x64-16 with Status Running.

STEP 5 Create the Application Database and User

Open PowerShell as Administrator and connect to PostgreSQL:

& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres

Enter the postgres password you set during installation. Then run these SQL commands:

CREATE DATABASE pump_intervention_db;
CREATE USER pump_user WITH ENCRYPTED PASSWORD 'replace_with_strong_password';
GRANT ALL PRIVILEGES ON DATABASE pump_intervention_db TO pump_user;
\q
Important: Replace replace_with_strong_password with a real strong password. You will need this in the .env file later.

STEP 6 Configure PostgreSQL for Production

Edit the configuration file at C:\Program Files\PostgreSQL\16\data\postgresql.conf.

Open it with Notepad as Administrator and find and update these lines:

# Only accept connections from this machine (security)
listen_addresses = 'localhost'

# Performance (adjust shared_buffers based on available RAM)
max_connections = 100
shared_buffers = 256MB
work_mem = 4MB
maintenance_work_mem = 64MB

# Logging
log_min_duration_statement = 1000
log_line_prefix = '%t [%p]: '

Also edit C:\Program Files\PostgreSQL\16\data\pg_hba.conf and make sure this line exists:

host    all             all             127.0.0.1/32            scram-sha-256

Restart PostgreSQL to apply changes:

Restart-Service -Name "postgresql-x64-16"

4. Phase 3 — GitHub Actions Self-Hosted Runner

The self-hosted runner is a small agent that runs on your server and listens for deployment jobs from GitHub. Every time you push to main, GitHub sends a job to this runner which pulls the code and deploys it.

STEP 7 Register the Runner on GitHub

  1. Go to your GitHub repository in a browser.
  2. Click Settings → Actions → Runners → New self-hosted runner.
  3. Select Windows as the operating system.
  4. GitHub will show you a set of PowerShell commands. Copy them exactly.

STEP 8 Install the Runner on the Server

Open PowerShell as Administrator on the server and run the commands GitHub gave you. They will look similar to this (use the exact commands from GitHub, not these):

# Example — use the real commands from GitHub
mkdir C:\actions-runner ; cd C:\actions-runner
Invoke-WebRequest -Uri https://github.com/actions/runner/releases/download/v2.xxx/actions-runner-win-x64-2.xxx.zip -OutFile actions-runner-win-x64-2.xxx.zip
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::ExtractToDirectory("$PWD\actions-runner-win-x64-2.xxx.zip", "$PWD")
.\config.cmd --url https://github.com/YOUR_USERNAME/pump-intervention-manager --token YOUR_TOKEN

During the config.cmd prompts:

  • Runner group: press Enter (default)
  • Runner name: type something like windows-server-prod
  • Labels: press Enter (default)
  • Work folder: press Enter (default)

STEP 9 Install the Runner as a Windows Service

This ensures the runner starts automatically when the server reboots:

.\svc.cmd install
.\svc.cmd start

Verify it appears as Online in your GitHub repo under Settings → Actions → Runners.

STEP 9b Fix Node.js and PM2 PATH for the Runner

This step is critical and often missed. The runner service runs under the Windows SYSTEM account, which does not automatically inherit the PATH of the user that installed Node.js and PM2. Without this fix, every deployment will fail with errors like 'npm' is not recognized as a command.

  1. Open File Explorer and navigate to C:\actions-runner\
  2. Look for a file named .env in that folder. If it does not exist, create a new text file and name it exactly .env (make sure Windows did not add .txt to the end — enable "Show file extensions" in Explorer to verify).
  3. Open the file in Notepad as Administrator and add this single line:
PATH=C:\Program Files\nodejs;C:\Users\Administrator\AppData\Roaming\npm;%PATH%
Note: If Node.js was installed for "all users" the path above is correct. If it was installed for a specific user, the npm folder may be at a different path. You can find it by running (Get-Command npm).Source in PowerShell.
  1. Save the file, then restart the runner service:
Restart-Service -Name (Get-Service | Where-Object { $_.DisplayName -like "*actions.runner*" }).Name
How to verify: After restarting, trigger a test deployment by pushing any small change to GitHub. In the Actions tab, the npm ci step should complete without errors.

6. Phase 5 — GitHub Actions Deployment Workflow

STEP 13 Create the Workflow File

In your local development machine, create the following file in your repository:

Path: .github/workflows/deploy.yml

name: Deploy to Production

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: self-hosted

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Install dependencies
        run: npm ci

      - name: Generate Prisma client
        run: npx prisma generate
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}

      - name: Run database migrations
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}

      - name: Build Next.js application
        run: npm run build
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          NEXTAUTH_URL: ${{ secrets.NEXTAUTH_URL }}
          NEXTAUTH_SECRET: ${{ secrets.NEXTAUTH_SECRET }}
          JWT_SECRET: ${{ secrets.JWT_SECRET }}
          MICROSOFT_TENANT_ID: ${{ secrets.MICROSOFT_TENANT_ID }}
          MICROSOFT_CLIENT_ID: ${{ secrets.MICROSOFT_CLIENT_ID }}
          MICROSOFT_CLIENT_SECRET: ${{ secrets.MICROSOFT_CLIENT_SECRET }}
          MICROSOFT_SENDER_EMAIL: ${{ secrets.MICROSOFT_SENDER_EMAIL }}

      - name: Restart application
        run: |
          pm2 restart pump-app --update-env || pm2 start npm --name "pump-app" -- start
          pm2 save

Commit and push this file to your repository:

git add .github/workflows/deploy.yml
git commit -m "ci: add production deployment workflow"
git push origin main
Result: From this point on, every git push to the main branch will automatically deploy the latest version to the server.

8. Phase 7 — IIS Reverse Proxy (Port 80)

IIS forwards incoming requests on port 80 to the Next.js app on port 3000. This is required so users can access the app without typing :3000 in the URL, and is also needed later for SSL/HTTPS.

STEP 16 Install IIS

  1. Open Server Manager.
  2. Click Manage → Add Roles and Features.
  3. Click Next until you reach Server Roles.
  4. Check Web Server (IIS) and click Next through all the screens.
  5. Click Install and wait for it to finish.

STEP 17 Install ARR and URL Rewrite Modules

These two free Microsoft modules are required for IIS to act as a reverse proxy.

  1. Download URL Rewrite from: iis.net/downloads/microsoft/url-rewrite
  2. Download Application Request Routing (ARR) from: iis.net/downloads/microsoft/application-request-routing
  3. Install both (run the installers, accept all defaults).
  4. Restart IIS after installing:
iisreset

STEP 18 Enable ARR Proxy

  1. Open IIS Manager (search for it in the Start menu).
  2. Click on the server name in the left panel (top level).
  3. Double-click Application Request Routing Cache.
  4. In the right panel click Server Proxy Settings.
  5. Check Enable proxy and click Apply.

STEP 18b Stop the IIS Default Web Site

IIS installs with a pre-existing site called Default Web Site that is already listening on port 80. If it is still running when you create the pump-app site, IIS will refuse to start the new site because two sites cannot share the same port. You must stop it first.

  1. In IIS Manager, expand the server node on the left → expand Sites.
  2. Click once on Default Web Site to select it.
  3. In the right-hand Actions panel, click Stop.
  4. The green arrow icon next to "Default Web Site" should disappear, confirming it is stopped.
Important: Do not delete the Default Web Site — just stop it. Stopping is reversible; deleting is not.

STEP 19 Configure the Website in IIS

  1. In IIS Manager, expand the server node on the left.
  2. Right-click Sites → Add Website.
  3. Fill in:
    • Site name: pump-app
    • Physical path: C:\apps\pump-intervention-manager\public
    • Binding type: http
    • IP address: All Unassigned
    • Port: 80
    • Host name: your domain (or leave blank for IP access)
  4. Click OK.

STEP 20 Add URL Rewrite Rule

  1. Click on the pump-app site in IIS Manager.
  2. Double-click URL Rewrite.
  3. Click Add Rule(s) → Blank rule (under Inbound rules).
  4. Fill in:
    • Name: Proxy to Next.js
    • Match URL — Requested URL: Matches the Pattern
    • Using: Regular Expressions
    • Pattern: (.*)
    • Action type: Rewrite
    • Rewrite URL: http://localhost:3000/{R:1}
  5. Click Apply.
Result: The app is now accessible at http://YOUR_SERVER_IP (no port number needed).

9. Phase 8 — Firewall Configuration

STEP 21 Open Port 80 for HTTP

New-NetFirewallRule -DisplayName "HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow

STEP 22 Open Port 443 for HTTPS (when ready)

New-NetFirewallRule -DisplayName "HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow

STEP 23 Keep PostgreSQL Port Closed

Since the app and database are on the same machine, PostgreSQL port 5432 should NOT be open to the internet. This is the default and you do not need to do anything — just verify:

# This should return nothing (no rule for port 5432)
Get-NetFirewallRule | Where-Object { $_.LocalPort -eq "5432" -and $_.Direction -eq "Inbound" }
Security: Never open port 5432 to the public internet. If you need to access the database remotely (e.g. from pgAdmin on your laptop), only allow your specific IP address and use a strong password.

STEP 23b Configure Port Forwarding on the Router

Opening the Windows Firewall (steps 21 and 22) is not enough on its own. If the server is connected to the internet through a router or modem (which is almost always the case in an office), the router also needs to be configured to forward incoming web traffic to the server.

When is this needed? If the server's IP address starts with 192.168. or 10. it is behind a router and you must do this step.

Find the server's local IP address

ipconfig

Look for IPv4 Address under the active network adapter. It will be something like 192.168.1.50. Write this down.

Set a static local IP (important)

Before configuring the router, make sure the server always gets the same local IP address. Otherwise the port forwarding will stop working after a reboot.

  1. Open Control Panel → Network and Sharing Center → Change adapter settings.
  2. Right-click the active network adapter → Properties.
  3. Double-click Internet Protocol Version 4 (TCP/IPv4).
  4. Select Use the following IP address and enter:
    • IP address: the current IP of the server (e.g. 192.168.1.50)
    • Subnet mask: 255.255.255.0
    • Default gateway: the router's IP (usually 192.168.1.1)
    • Preferred DNS: 8.8.8.8
  5. Click OK.

Configure port forwarding on the router

Every router brand has a different interface, but the steps are similar:

  1. Open a browser on the server and go to http://192.168.1.1 (or whatever the router's IP is — printed on the router label).
  2. Log in with the router admin credentials (also on the router label if never changed).
  3. Find the section called Port Forwarding, Virtual Server, or NAT (depends on the router brand).
  4. Add two forwarding rules:
Rule nameExternal portInternal IPInternal portProtocol
HTTP80192.168.1.50 (server IP)80TCP
HTTPS443192.168.1.50 (server IP)443TCP
  1. Save and apply. The router may reboot.
How to verify: From a phone on mobile data (not the same WiFi), open a browser and go to http://YOUR_PUBLIC_IP. You should see the app login page. Find the public IP by running: (Invoke-WebRequest -Uri "https://api.ipify.org" -UseBasicParsing).Content

10. Phase 9 — Automatic Database Backups

STEP 24 Create the Backup Script

Create the directory and script file:

mkdir C:\scripts
mkdir C:\backups\postgres

Create the file C:\scripts\backup-db.ps1 with this content:

$date = Get-Date -Format "yyyy-MM-dd_HH-mm"
$backupDir = "C:\backups\postgres"
$backupFile = "$backupDir\pump_db_$date.dump"
$pgDump = "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe"

if (!(Test-Path $backupDir)) { New-Item -ItemType Directory -Path $backupDir }

$env:PGPASSWORD = "replace_with_strong_password"
& $pgDump -U pump_user -h localhost -Fc pump_intervention_db -f $backupFile

# Keep only the last 30 backups (30 days)
Get-ChildItem $backupDir -Filter "*.dump" |
    Sort-Object LastWriteTime -Descending |
    Select-Object -Skip 30 |
    Remove-Item -Force

Write-Host "Backup completed: $backupFile"
Important: Replace replace_with_strong_password in the script with your actual pump_user database password.

STEP 25 Schedule Daily Backups

Run this in PowerShell as Administrator to create a scheduled task that runs every day at 2:00 AM:

$action = New-ScheduledTaskAction `
    -Execute "PowerShell.exe" `
    -Argument "-NonInteractive -File C:\scripts\backup-db.ps1"

$trigger = New-ScheduledTaskTrigger -Daily -At "02:00AM"

$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit (New-TimeSpan -Hours 1)

Register-ScheduledTask `
    -TaskName "PostgreSQL Daily Backup" `
    -Action $action `
    -Trigger $trigger `
    -Settings $settings `
    -RunLevel Highest `
    -Force

Test the backup manually

& "C:\scripts\backup-db.ps1"

Check that a .dump file appears in C:\backups\postgres\.

How to restore from a backup

$env:PGPASSWORD = "replace_with_strong_password"
& "C:\Program Files\PostgreSQL\16\bin\pg_restore.exe" `
    -U pump_user `
    -h localhost `
    -d pump_intervention_db `
    -c `
    "C:\backups\postgres\pump_db_2026-06-01_02-00.dump"

11. Phase 10 — SSL / HTTPS (Recommended)

If the server has a domain name, you can add a free SSL certificate using Win-ACME (Let's Encrypt for Windows IIS).

STEP 26 Install Win-ACME

  1. Download Win-ACME from github.com/win-acme/win-acme/releases (download the win-acme.v2.x.x.x64.pluggable.zip)

12. Phase 11 — Subdomain Setup (guimabombas.com)

The app can be hosted on a subdomain of guimabombas.com, for example app.guimabombas.com. This requires a DNS record, an IIS binding update, and a new SSL certificate.

STEP 28 Choose a Subdomain

Decide on the subdomain prefix. Common options:

Example URLWhen to use
app.guimabombas.comGeneric, works for any application
manutencao.guimabombas.comDescriptive in Portuguese
bombas.guimabombas.comShort and domain-related
gestao.guimabombas.comManagement-focused naming

The examples below use app.guimabombas.com — replace with whichever prefix the client chooses.

STEP 29 Add a DNS Record

Log in to the DNS provider or domain registrar where guimabombas.com is managed (e.g. GoDaddy, Cloudflare, OVH, etc.) and add the following record:

TypeNameValueTTL
AappThe server's public IP address3600
How to find the server's public IP: On the server, open PowerShell and run: (Invoke-WebRequest -Uri "https://api.ipify.org" -UseBasicParsing).Content
DNS propagation: The DNS change can take between a few minutes and 48 hours to be visible worldwide. You can check propagation progress at dnschecker.org.

STEP 30 Update the IIS Site Binding

  1. Open IIS Manager.
  2. Expand Sites and click on pump-app.
  3. In the right panel, click Bindings.
  4. Select the existing HTTP binding and click Edit.
  5. In the Host name field type: app.guimabombas.com
  6. Click OK.

STEP 31 Get an SSL Certificate for the Subdomain

Once the DNS record is live and pointing to the server, run Win-ACME to issue a Let's Encrypt certificate for the subdomain:

cd C:\tools\win-acme
.\wacs.exe

Follow the prompts:

  1. Choose N — Create certificate (default settings)
  2. Choose 1 — IIS
  3. Select the pump-app site
  4. Confirm the domain app.guimabombas.com
  5. Enter the client's email address (for certificate expiry alerts)

Win-ACME will install the certificate in IIS and configure auto-renewal automatically. It will also add an HTTPS binding (port 443) to the IIS site.

Result: The app is now accessible at https://app.guimabombas.com with a valid SSL certificate.

STEP 32 Update NEXTAUTH_URL to the Subdomain

Update the URL in both places:

1. On the server — edit C:\apps\pump-intervention-manager\.env and change:

NEXTAUTH_URL="https://app.guimabombas.com"

2. On GitHub — go to your repository → Settings → Secrets and variables → Actions → update the NEXTAUTH_URL secret to https://app.guimabombas.com.

Then restart the app to apply the change:

pm2 restart pump-app --update-env

STEP 33 Add HTTPS Redirect in IIS (optional but recommended)

Force all HTTP traffic to redirect to HTTPS automatically:

  1. In IIS Manager, click on the pump-app site.
  2. Double-click URL Rewrite.
  3. Click Add Rule(s) → Blank rule.
  4. Fill in:
    • Name: Force HTTPS
    • Match URL — Pattern: (.*)
    • Add a Condition: Input {HTTPS}, Pattern ^OFF$
    • Action type: Redirect
    • Redirect URL: https://{HTTP_HOST}/{R:1}
    • Redirect type: 301 Permanent
  5. Click Apply.

Then inside the psql prompt, ask the developer (Nuno Freitas) for the exact SQL to insert the first admin user, as it depends on the app's user table structure and password hashing method. It will look something like:

Important: Never store plain text passwords. The password must be hashed using the same method the app uses (bcrypt). Ask the developer to provide the exact insert command with a pre-hashed password for the initial admin account.

14. Phase 13 — PM2 Log Rotation

By default, PM2 writes application logs to files that grow indefinitely. Over weeks or months these files can fill the server's disk and cause the app to crash. Log rotation automatically archives and deletes old logs.

STEP 36 Install PM2 Log Rotate Module

pm2 install pm2-logrotate

STEP 37 Configure Log Rotation

# Maximum size of a single log file before it is rotated
pm2 set pm2-logrotate:max_size 50M

# Number of rotated log files to keep (7 = one week of history)
pm2 set pm2-logrotate:retain 7

# Run rotation check every day at midnight
pm2 set pm2-logrotate:rotateInterval "0 0 * * *"

# Compress old log files to save disk space
pm2 set pm2-logrotate:compress true

STEP 38 Check Log File Locations

# Show where PM2 stores logs
pm2 info pump-app

Log files are typically stored in C:\Users\Administrator\.pm2\logs\.

15. Phase 14 — Post-Reboot Verification Checklist

After the initial setup is complete, reboot the server once and verify that everything comes back up automatically. Non-technical users will not think to test this — a reboot should be done before going live so any startup issues are found in advance rather than during real use.

STEP 39 Reboot the Server

Restart-Computer

17. Phase 16 — Remote Desktop (RDP) Access

Remote Desktop lets you manage the server from any Windows computer without being physically present. This is how the client (and you) will access the server for maintenance.

STEP 42 Enable Remote Desktop on the Server

  1. Open Server Manager.
  2. Click Local Server in the left panel.
  3. Find Remote Desktop and click the link next to it (it says "Disabled").
  4. Select Allow remote connections to this computer.
  5. Uncheck Allow connections only from computers running Remote Desktop with Network Level Authentication if you need to connect from older Windows versions.
  6. Click OK.

STEP 43 Open the RDP Port in Windows Firewall

New-NetFirewallRule -DisplayName "Remote Desktop" -Direction Inbound -Protocol TCP -LocalPort 3389 -Action Allow
Security: Port 3389 (RDP) is frequently targeted by automated attacks on the internet. To reduce risk, only allow RDP from specific IP addresses (your office or home IP): New-NetFirewallRule -DisplayName "RDP" -Direction Inbound -Protocol TCP -LocalPort 3389 -RemoteAddress YOUR_IP -Action Allow

STEP 44 Connect via Remote Desktop

From any Windows computer:

  1. Press Win + R, type mstsc and press Enter.
  2. In the Computer field, enter the server's public IP address or domain (e.g. app.guimabombas.com).
  3. Click Connect.
  4. Enter the Windows Server administrator username and password.
From a Mac: Download Microsoft Remote Desktop from the App Store (free). The connection steps are the same.

STEP 46 Set Up a Disk Space Alert (optional)

To avoid the server running out of disk space (from logs, backups, or Windows updates), create a scheduled alert:

# Save this as C:\scripts\check-disk.ps1
$drive = Get-PSDrive -Name C
$freeGB = [math]::Round($drive.Free / 1GB, 1)
$totalGB = [math]::Round(($drive.Used + $drive.Free) / 1GB, 1)
$freePercent = [math]::Round(($drive.Free / ($drive.Used + $drive.Free)) * 100, 0)

if ($freePercent -lt 20) {
    $subject = "WARNING: Low disk space on server ($freeGB GB free of $totalGB GB)"
    $body = "Server disk space is low. $freeGB GB free ($freePercent%). Please clean up old backups or logs."
    Send-MailMessage -To "admin@guimabombas.com" -From "server@guimabombas.com" `
        -Subject $subject -Body $body -SmtpServer "smtp.yourmailprovider.com"
}

Schedule it to run daily (same way as the database backup — see Phase 9, STEP 25).
